# anki-tetris-card

Addon for [anki](https://apps.ankiweb.net/) adding a Tetris card type
for reviewing setups such as openers or PC setups.

## Usage

TBA for installation

Controls can be set through config file with add-ons found in
Tools -> Add-ons -> anki-tetris-card

Controls are likely to conflict with anki's shortcuts, which I recommend
installing an add-on to set anki's shortcuts such as [Customize Keyboard Shortcuts](https://ankiweb.net/shared/info/1762336370).

## Fields

### Queue Pattern

The pattern for queues follows [Extended Sfinder Pieces](https://github.com/Marfung37/ExtendedSfinderPieces).

| Property     | Definition                                                                                 |
| ------------ | ------------------------------------------------------------------------------------------ |
| Soundness    | Every queue generated covers the setup. No invalid queues are included.                    |
| Completeness | Every queue that covers the setup is generated by the pattern. No valid queues are missed. |
| Exactness    | Pattern is both sound and complete.                                                        |

A pattern for the card should be complete to provide reviewers
most general description of the coverage of the setup.
If a pattern is not sound, [cover mask](#cover-mask) field provides a way
to exclude invalid queues.
Ideally, the pattern is exact, but to create a useful exact pattern
in terms of being able to be described with few conditions
is a difficult problem.

### Field

A [fumen](https://harddrop.com/wiki/Fumen) for the initial state of the board.
Only the first page will be considered.
If left empty, the board will start empty.

### Goal

A description or name for the goal of this card.
This may be needed to give direction for the reviewer.

### Answer

A [fumen](https://harddrop.com/wiki/Fumen) for the finial state of the board.
The fumen may be multiple pages to allow for multiple valid solutions,
which may be needed to increase the coverage of the setup.
Fumens separated by newlines denote required steps, such as
each fumen is placement of each bag of a 5-bag opener or an OQB PC setup

### Refill Bags

A boolean for whether after the queue pattern to refill queue with new bags.

### Cover Mask

A hexstring to act as a bitmask of which queues from the
[queue pattern](#queue-pattern) is a valid queue.
If left empty, the queue pattern is assumed to be sound.

For example: `bfe` would express every queue except for the
second and last generated queue is a valid queue.

If the number of generated queues not a multiple of 4, pad the bitmask with 0's
for the hexstring cover mask.
